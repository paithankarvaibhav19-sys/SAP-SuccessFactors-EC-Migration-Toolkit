## 1. Business Objective & Scenario

GlobalTech Solutions is migrating from a legacy HRMS to SAP SuccessFactors Employee Central. This specification establishes the organizational data model, segregates Generic Objects (MDF) from Classic Foundation Objects (FO), and defines field-level cascading association rules to prevent invalid organizational data entry across global offices.

---

## 2. Organizational Hierarchy Architecture

The corporate structure enforces a strict 4-tier hierarchy. Lower-level objects inherit access and filtering context from their immediate parent entity.

```text
[ Legal Entity (GT_US / GT_IN) ]
    │
    └── [ Business Unit (BU_ENT / BU_CLOUD) ]
            │
            └── [ Division (DIV_HCM / DIV_INFRA) ]
                    │
                    └── [ Department (DEP_L2_SUPP / DEP_ENG) ]

### 5.2.1 Key Implementation Notes: Corporate Data Model XML

* **Governance & Upload:** The Corporate Data Model (`corporate-data-model.xml`) governs Foundation Objects (FO) and is uploaded via **Provisioning** (`Provisioning > Managing Document Types > Succession Management > Import/Export Corporate Data Model`) or synchronized via **Business Configuration UI (BCUI)**.
* **Field Properties:**
  * `externalCode`: The immutable primary key (max-length 32) referenced during delta API extractions and data loads.
  * `status`: Enforces record lifecycle (`A` = Active, `I` = Inactive). Inactive records remain available for historical reporting but are hidden from front-end dropdowns.
  * `timezone`: Standardized Olson time zone identifier required for accurate Effective Dating calculations across distributed geographies.
* **MDF Migration Path:** While `Location` remains configured here as a Classic Foundation Object, standard organizational units (`LegalEntity`, `BusinessUnit`, `Division`, `Department`, `CostCenter`) are maintained as Generic Objects under the Metadata Framework (MDF) to enable rule-driven UI behavior and dynamic permissions.
* **Country-Specific Overrides:** Address format rules, postal code masks, and state picklists for locations in specific regions are declared in the companion file `country-specific-corporate-data-model.xml`.
