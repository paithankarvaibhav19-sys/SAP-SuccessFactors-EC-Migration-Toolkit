## 1. Business Objective & Scope

This specification establishes an enterprise **Position-Controlled Workforce Hierarchy** in SAP SuccessFactors Employee Central. It transitions legacy ad-hoc job assignments into a structured Metadata Framework (MDF) Position architecture.

The scope defines:
* The MDF `Position` object schema.
* Automated `Pos2Job` attribute inheritance to `jobInfo`.
* Position matrix reporting relationships (dotted-line governance).
* In-memory rule execution mechanics via the **Job Information Model**.
* Headcount vacancy enforcement and operational L2 support remediation SOPs.

3. In-Depth Architectural Concept: Job Information vs. Job Information Model

When authoring business logic in SAP SuccessFactors, choosing between the static base object and the transient model object dictates how the system evaluates rules.

### 3.1 Architectural Comparison: Job Information vs. Job Information Model

| Dimension | `Job Information` <br>*(Static Base Object)* | `Job Information Model` <br>*(Dynamic Working State)* | Operational Impact & Why It Matters |
| :--- | :--- | :--- | :--- |
| **System State** | • Committed database record.<br>• Currently saved on the employee profile. | • Live, in-memory working buffer.<br>• Unsaved draft state during active user entry. | `Job Information` reflects past persisted truth; `Job Information Model` captures real-time changes happening on screen. |
| **Delta Tracking** | • Reads **Current Saved Value** only.<br>• Blind to unsaved field changes in the active session. | • Reads **Current Value** AND **Previous Value** (`Model.Previous`). | Mandatory for change detection (e.g., detecting if `Department` changed from IT to HR). |
| **Trigger Hook Support** | • Primarily `onView` or batch read integrations.<br>• Not suited for dynamic UI interaction. | • Mandatory for `onChange`, `onInit`, and `onSave`.<br>• Core driver for **Event-Reason Derivation (ERD)**. | Using `Job Information` on an `onChange` rule will fail to retrieve new unsaved dropdown selections. |
| **Configuration Path** | `Admin Center` $\rightarrow$ `Configure Business Rules`<br>**Base Object:** `Job Information` | `Admin Center` $\rightarrow$ `Configure Business Rules`<br>**Base Object:** `Job Information Model` | Rules requiring field auto-population, delta checks, or validations must always select the **Model** variant. |
